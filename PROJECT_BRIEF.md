
# Plaque Proof Studio - project brief
 
You are my senior full-stack engineer and product designer. We are building "Plaque Proof Studio", an internal production tool for Impact Signs (https://www.impactsigns.com), a U.S. maker of cast bronze and cast aluminum plaques. I will sell this tool to Impact Signs, so it must look and behave like a premium in-house product, not a demo. I am not a developer: explain decisions briefly, keep the README current, and never leave me with steps you could have automated.
 
## 1. The workflow the app implements
1. A designer pastes a plaque spec as plain text, then adds the customer's logo, image(s), wording (typed, or a .docx), and optionally a customer SKETCH.
2. The app parses the spec into structured fields using only options in data/catalog.json, shows what it understood, and flags every assumption.
3. The app generates THREE concept images with OpenAI model gpt-image-2.5-sunburst. These explore look and layout. They are NOT the proof.
4. Under each concept an edit bar lets the designer type a small change ("make the border thinner"). Only that thing changes, producing a new version of the same concept. Every version is kept.
5. The designer picks a concept; its layout choices (image size/position, text alignment/scale, logo slot, border) are extracted into the structured spec and can be fine-tuned with simple controls.
6. The app builds the customer PROOF in Impact Signs' exact sheet format. The plaque on the proof is drawn by CODE from the structured spec. Optional toggle: use the approved AI image instead.
7. Optionally the app creates a true-vector PRODUCTION PDF following Impact Signs' production conventions.
 
## 2. Principles (non-negotiable)
P1. The image model is used ONLY for concepts and refinement. Anything that must be exact (wording, dimensions, logos, swatches, labels, proof, production art) is generated by code from structured data.
P2. data/catalog.json is the single source of truth. Never invent a finish, color, border, font, image type, mounting, rosette, size or price. If something is not in the catalog, say "not currently available" and offer the nearest valid options. The UI, parser and validator must all read the catalog.
P3. Typed customer wording is reproduced character for character: no autocorrect, straight quotes stay straight (the real Heritage plaque keeps Ed's and 'Onward' with straight marks). Only strip trailing spaces and say so. Suspected typos are FLAGGED, not fixed. Text transcribed from handwriting must be confirmed by the designer, and curly quotes are applied by default as a switchable assumption.
P4. API keys exist only as server environment variables. Never in the repo, the browser, logs, or test fixtures.
P5. Never overwrite. Every generation or edit is a new immutable version with a parent id.
P6. Never lag. The UI never blocks on a generation; long jobs stream progress.
P7. The ORDER (written spec) beats the customer's sketch when they disagree. Show the conflict as a visible flag.

## 5b. Image prompt library (this IS the "system prompt" for the image model)
The Images API has no system-prompt field and nothing saved on OpenAI's side. Every call's `prompt` parameter must carry all instructions. Build each prompt as: HOUSE RULES + MODE TEMPLATE (concept or edit) + JOB DETAILS filled from the structured spec. Store these as editable text files in server/prompts/ (house_rules.md, concept.md, edit.md, wording_fix.md, reference_roles.md), NOT hard-coded in TypeScript, show them read-only at /admin/prompts, and save the exact final prompt text and the template version on every Version record for traceability. Start with this text, and improve wording if you find better, recording changes in docs/DECISIONS.md.
 
HOUSE RULES (prepended to EVERY image call):
"You are rendering a concept preview of a single cast metal architectural plaque for Impact Signs.
1. Show exactly one plaque, fully visible, centered, flat-on, on a plain neutral wall. Soft diffuse light, subtle shadow, generous margin on all sides.
2. Reference image 1 is the LAYOUT. Copy its proportions, slot positions and text positions exactly. Do not move, resize or reflow anything.
3. TEXT: render only the text listed under TEXT, spelled, capitalized and punctuated exactly as given. No extra words, no placeholder text, no watermark. If a line will not fit, make it smaller; never rewrite or drop it.
4. MATERIALS: match the supplied swatch references for finish, paint color, texture and border. Raised elements (lettering, border, image frame) share the plate's metal finish. The background field is recessed and paint-filled.
5. LOGO AND CUSTOMER IMAGE: use the supplied files as given. Never redraw, restyle, re-letter, recolor or crop a logo.
6. Add nothing that was not requested: no screws, rosettes, ornaments, extra borders, people, hands, tools, props or branding.
7. Photographic realism. No illustration, no cartoon, no 3D-render look."
 
REFERENCE ROLES (list only the references actually sent, in order):
"Reference 1 = layout skeleton. Reference 2 = finish swatch (match its color and sheen). Reference 3 = background paint swatch. Reference 4 = background texture swatch. Reference 5 = border style. Reference 6 = customer logo. Reference 7 = customer image. [rosette, mounting etc. only if relevant]"
 
CONCEPT TEMPLATE:
"CONCEPT MODE. Direction: {A Ceremonial | B Editorial | C Monument} - {one-sentence description of that direction's layout choices}.
PLAQUE: {material}, {W} by {H} inches, {orientation}. Finish: {finish label}. Lettering: {raised|recessed}. Background field: recessed, paint-filled {color label}, {texture label} texture. Border: {border label}, {raised|flat}. Image: {image type label} of the supplied {portrait|landscape} image, placed {slot}, shown as a monotone relief inside a thin raised frame. Logo: {slot or 'none'}. Layout: {text-only | image-and-text}.
TEXT (verbatim, in order, centered unless the layout says otherwise):
{each line on its own line}"
 
EDIT TEMPLATE:
"EDIT MODE. Image 1 is the current plaque. Apply ONLY this change: {instruction restated plainly}. Keep everything else exactly as it is: {for each ON lock chip: 'the wording', 'the layout and positions', 'the colors', 'the finish', 'the border', 'the image', 'the logo'}. Do not change any word, letter, logo or image. Do not alter the camera angle, lighting, background, plaque proportions, or the position or size of anything not mentioned. If the change cannot be made without altering something locked, make the smallest possible change and leave the rest untouched."
Region edit (when a mask is sent) adds: "The mask marks the ONLY area you may change; everything outside it must remain identical."
 
WORDING FIX (one automatic retry after the vision check fails):
"The previous result had wording errors: expected '{expected}' but the image shows '{seen}'. Correct ONLY those words. Change nothing else."
 
Edit instructions are first validated against data/catalog.json with the Anthropic adapter and restated plainly (for example "make the border thinner" -> "reduce the raised border width by about one third"). Requests for anything not in the catalog are refused before any image call.
Anthropic (text and vision): model from ANTHROPIC_MODEL (claude-sonnet-5-5). Uses: parse spec into strict JSON, split customer wording into roles, transcribe sketches with bounding boxes and confidence, validate edit instructions against the catalog, and check that wording in a generated image matches (strict JSON {ok, differences}). Validate all JSON with zod and retry once on invalid output.
Provide GET /api/health that reports, in plain English: server OK, mock or live, each key present/absent, and one cheap live call per provider when asked.

Rules: sizes in many written forms, width first; "Dark Oxide or Leatherette" and "Black Leatherette" mean background COLOR then TEXTURE; "relief image" with no detail -> Photo Relief as an ASSUMPTION; a border mentioned without a style -> Single Line as an ASSUMPTION; font not stated -> Times New Roman as an ASSUMPTION; "Text-only layout" -> no image slot, no logo slot, one centered text block unless a sketch dictates otherwise; "Blind mounting"/"Blind stud mounting" -> blind stud; "Satin" -> that material's satin/brushed finish. Anything not in the catalog goes in an "unavailable" list with nearest valid options.
Layout rules (stated by the product owner): portrait image -> TOP slot; landscape image -> LEFT slot; logo -> TOP, MIDDLE or BOTTOM. Proposed tie-breaks (mark as proposals): portrait on top + logo -> logo bottom; landscape left + logo -> logo top of the text column; a logo never overlaps the image slot.
Customer text roles: headline, subhead, body[], footer. Heritage: line 1 "Edwin J. Feulner Jr., Founder", line 2 "The Heritage Foundation", body = the paragraph. Charlie's: title in the customer's handwriting ("Charlie's Field #3", with "#3" indented), then two all-caps lines: DEDICATED NOVEMBER 19, 2025 / IN LOVING MEMORY OF CHARLIE "CHUCK" APONICK (the finished plaque used curly quotes).
Sketch handling: a sketch is often a phone photo saved as a PDF (one skewed JPEG with shadow edges). Extract, deskew, crop; transcribe each line with bounding box and confidence plus a description of the layout (border lines, corner marks, indents); show the transcription beside the sketch; NOTHING downstream runs until the designer confirms it. Per line the designer chooses "typeset in a font" or "use the customer's handwriting" (trace to vector paths with potrace, keep slant and relative position, with threshold/smoothing sliders and an overlay). Image resolution: show effective ppi at the frame size and warn under 150 ppi (warn, do not block).
 
## 9. Rendering and output rules
PlaqueRenderer: one function producing an SVG from the structured spec at any scale, layers bottom to top: plate (finish color), field (inset by border width, paint color + seamless texture tile tinted by paint color; border "none" runs the field to the edge), border (single = plain 0.25 in frame measured above), text (opentype.js outlines in plate color; traced handwriting uses its paths; never live text on the plaque), image frame (fractions above; customer image multiplied over the plate color; convert color photos to greyscale first), effects (quiet drop shadow, emboss, satin sheen via SVG filters; debug switch to turn off). The proof and the concept layout-skeleton both use it.
Proof output: vector PDF (fonts embedded) plus 150-dpi PNG. PROOF_VISUAL_MODE = "code" (default) or "ai_concept".
Production PDF: follow section 7 exactly. ALL text outlined; auto-fit text but never below 0.25 in (all caps) or 0.375 in (mixed case) letter height; if a licensed font file is missing from server/fonts/ say which one and stop - never silently substitute (open stand-ins are for previews only and must be labelled). Raster logos are NOT embedded: place a labelled placeholder and mark "LOGO NEEDS VECTOR". Put the spec JSON and project number in PDF metadata. A PDF-compatible Illustrator file is just a PDF: deliver .pdf and tell the designer to Save As .ai in Illustrator; do not rename. File name [project number]_[short-name]_[W]x[H]_production.pdf.
PREFLIGHT after creating a production file, shown in the UI: page size = W*72 x H*72 within 0.1 pt; no fonts in the file; raster image count 0 (scan for /Subtype /Image); only #231F20 and white used; text minimums met; logo vector yes/no; border geometry VERIFIED (single/none) or UNVERIFIED (double/bevel). Failures in red with the fix.
Proof-diff tool at /admin/proof-diff: rasterize a real reference PDF and the generated proof at 150 dpi, show side by side with a difference heat-map and mean difference per region (plaque, right column, footer). Tests assert layout regions within 2 pt; colors and effects are tuned by eye with this tool.
